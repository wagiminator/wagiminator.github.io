WCH USB Programmer

Flash WCH microcontrollers over USB with their built-in bootloader, no programmer needed. Supports the CH54x, CH55x, CH56x, CH57x, CH58x, CH59x, CH643, CH32F103/20x, CH32V103/20x/30x, CH32X03x and CH32L103 with bootloader version 2.x.

This browser cannot access USB devices. Open this page in Chrome, Edge or Opera on a desktop computer.

Firmware

    Put the chip into bootloader mode, then choose Flash firmware and select the bootloader in the list the browser shows. The firmware is written, verified, and the chip restarts with it.

    Entering bootloader mode

    Connect the chip by USB while its boot pin or button is active. The board then shows up as a USB device, not as its usual function. Typical ways:

    • CH55x: pull D+ (P3.6) to 3.3 V through a 10 kΩ resistor while plugging in, or hold the board's BOOT button.
    • CH32F/V/X/L: set BOOT0 high (or hold the BOOT button) while plugging in or resetting.
    • CH56x, CH57x, CH58x, CH59x: activate the chip's download pin (often a BOOT button on the board) while plugging in.
    • Firmware with a bootloader jump: some programs can restart into the bootloader themselves.

    Details depend on the chip and board; see the board's documentation.

    Not connected

    Put the chip into bootloader mode and connect it.

    Driver setup

    Windows: the browser needs the WinUSB driver for the bootloader. Put the chip into bootloader mode, start Zadig, choose Options, List All Devices, select the WCH device (USB ID 4348:55E0 or 1A86:55E0) and install WinUSB. The libusb-win32 driver that chprog uses does not work in the browser.

    Linux: allow access to the device:

    echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="4348", ATTR{idProduct}=="55e0", MODE="666"' | sudo tee /etc/udev/rules.d/99-ch55x.rules
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="1a86", ATTR{idProduct}=="55e0", MODE="666"' | sudo tee -a /etc/udev/rules.d/99-ch55x.rules
sudo udevadm control --reload-rules

    macOS: no driver needed.
